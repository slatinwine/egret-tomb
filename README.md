# 白鹭冢 · 盗墓文字冒险

AI 主理人驱动的对话式文字冒险。灵感致敬楳图一雄《漂流教室》，舞台为完全原创的中国盗墓设定：一支 12 人考古队在入墓当夜连人带墓被剥离原时代，封入遥远未来的地底战国王墓。

## 访问入口

- **主站（WorkBuddy 托管，推荐）**：https://drifting-classroom.app.workbuddy.host/?sharecode=MYVEVIDCBE
- **镜像（GitHub Pages）**：https://slatinwine.github.io/egret-tomb/ （经沙箱数据桥转发云端 AI 请求，体验与主站一致）

## 玩法

- **对话即冒险**：把想做的事直接告诉 AI 主理人（自由输入），或点它给的行动建议
- **状态系统**：第 X 天 · 时段（清晨/正午/黄昏/深夜）· 地点 · 体力 · 精神 · 物品栏，由主理人每回合判定增减
- **生死判定**：体力归零即死亡，精神归零即发疯；也存在极难达成的好结局（逃出荒漠 / 幸存者聚落 / 未来的真相）
- **纸条之海（漂流瓶机制）**：每次谢幕可留一张 ≤40 字的纸条漂进时间之海，会出现在（这台机器上的）后续冒险里；白天数推进时有机会捡到前人的遗言——8 张种子纸条来自"旧时代的漂流者"
- **时光机（有限穿越）**：广播室抽屉里那台指针倒走的旧电波表，是「回声」时间装置的便携终端。找到后解锁，充能仅 **3 次**，每次窥视过去/未来都会消耗 1 次充能、冲击精神并流逝时间——且必然揭示一条线索
- **线索与真结局**：共 5 条线索（C1–C5）藏在过去与未来中，探索中也可能自然撞见。集齐 ≥4 条并**说出正确推理**——人类毁灭于自己创造的 AI「白箱」——才触发真结局「真相」；线索不足时即使推理也不会被承认
- **生存档案**：记录每一次漂流的生存天数与结局
- **自动存档**：每回合落盘，关掉页面可「继续上次」

## AI 主理人（WorkBuddy 云端 AI，免密钥）

**主通道为 WorkBuddy 云服务 LLM**：应用初始化 `@tencent-ai/workbuddy-cloud-sdk`（同源托管 `workbuddy-cloud-sdk.global.js`，加载失败回退 CDN），用 `publicConfig`（endpoint + publishableKey）创建客户端，免密钥直连——玩家打开链接即玩，无需任何配置。

**跨源镜像（GitHub Pages）**：云平台 API 按 Origin 白名单放行（仅应用自身域名），镜像域名直连会被 403 拒绝。解法同赛博漂流瓶：页面检测到非应用域名时，加载 `bridge.html` 沙箱 iframe（`sandbox="allow-scripts"` → 不透明源，请求 Origin 为 null，网关放行并回显 `Access-Control-Allow-Origin: null`），所有云端请求经 postMessage 由桥代发；SDK 初始化时传入自定义 `fetch`（`bridgeFetch`），LLM 长请求超时放宽至 120 秒。同源访问时一切直连，桥不参与。

- **模型策略**：拉取云端模型列表，按偏好选 `glm-5.3-flash`（快、文笔好）→ `hunyuan-chat`（极速纯正文）→ 列表第一个可用模型
- **协议**：仅支持流式（`stream: true` 强制），客户端收集完整文本后按打字机节奏呈现；每回合 `messages[0]` 为应用持有的 system prompt，`conversationId` 绑定本次漂流（runId）
- **备用通道**：云端不可达时，可在「AI 通道」面板配置任意 OpenAI 兼容接口（密钥只存本机浏览器，请求浏览器直发）

> 协议：主理人每回合必须返回严格 JSON（叙事 + 状态 + 选项 + 结局），客户端做钳制校验，模型越界也会被拉回。

## 核心协议

```json
{
  "narration": "150~350字叙事",
  "state": { "day":1, "time":"清晨", "location":"六年二班教室", "hp":80, "sanity":70, "inventory":["半瓶水"] },
  "options": ["建议一", "建议二"],
  "ending": null
}
```
